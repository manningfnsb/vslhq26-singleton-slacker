## Section 3: Technical Architecture Response

### 3.1 Cloud Platform

Our solution is built on Microsoft Azure Government, hosted in US sovereign cloud regions (US Gov Virginia and US Gov Arizona). Key platform capabilities:

**Hybrid Architecture**: We will deploy Azure Arc to extend Azure management to the Borough's existing VMware environment, providing a single pane of glass for both on-premises and cloud workloads. Azure Stack HCI can be deployed on-premises for workloads requiring local data residency.

**Availability**: Azure Government provides 99.9% uptime SLA for virtual machines. Our architecture uses paired regions with manual failover procedures (estimated 45-60 minutes).

**Operating Systems**: Full support for Windows Server 2019, 2022, and 2025 as well as Linux distributions including RHEL 8/9, Ubuntu 22.04/24.04, and SUSE Linux Enterprise.

**Containers**: Azure Kubernetes Service (AKS) with managed control plane, integrated with Azure Container Registry and Azure Policy for governance.

**Infrastructure as Code**: Native support for Terraform (with AzureRM provider), Bicep, and ARM templates. We recommend Bicep for new deployments with Terraform for multi-cloud scenarios.

**Serverless**: Azure Functions (consumption and premium plans), Azure Logic Apps, and Azure Event Grid for event-driven architectures.



**Managed Databases**: Azure SQL (SQL Server compatible), Azure Database for PostgreSQL Flexible Server, and Azure Cosmos DB (MongoDB API compatible).

### 3.2 Networking

**Private Connectivity**: We will provision a 1 Gbps Azure ExpressRoute circuit from the Borough's primary facility to Azure Government US Gov Virginia, with a 500 Mbps secondary circuit to US Gov Arizona for redundancy.

**Network Segmentation**: Azure Virtual Networks with Network Security Groups (NSGs) and Azure Firewall provide macro and micro-segmentation. Azure Private Link ensures PaaS services are accessed over private endpoints.

**DDoS Protection**: Azure DDoS Protection Standard is included for all public-facing endpoints with adaptive tuning and mitigation analytics.

**IPv4**: Full IPv4 support. IPv6 is not currently supported in our Government cloud deployment.

**DNS**: Azure DNS for Borough domains. DNSSEC is not available in Azure Government at this time.

**WAF**: Azure Web Application Firewall with OWASP 3.2 rule set, bot protection, and custom rules for Borough-specific requirements.

**VPN Backup**: Site-to-site VPN tunnels configured as automatic failover for ExpressRoute. BGP routing ensures seamless failover within 30 seconds.



### 3.3 Storage

**Object Storage**: Azure Blob Storage with 99.999999999% (11 nines) durability in LRS configuration, with GRS providing 16 nines durability for critical data.

**Tiered Storage**: Hot, Cool, Cold, and Archive tiers with automated lifecycle management policies. We will configure policies aligned with Borough data classification.

**Block Storage**: Azure Managed Disks with Premium SSD v2 providing configurable IOPS (up to 80,000) and throughput (up to 1,200 MB/s) with SLA-backed guarantees.

**File Storage**: Azure Files with SMB 2.1 support. NFS is in preview and not available in Government regions.

**Immutable Storage**: WORM policies for Blob Storage only. Other storage types planned for future.

**Encryption**: AES-256 encryption at rest for all storage services. Customer-managed keys via Azure Key Vault (FIPS 140-2 Level 3 validated HSM) available for all services.

**Cross-Region Replication**: GRS and GZRS replication with configurable RPO (typically 15 minutes or less for async replication).





**Backup and Recovery**: Azure Backup with file-level, volume-level, and application-consistent recovery options. Cross-region restore for disaster recovery scenarios.

## Section 4: Security Response

### 4.1 Identity and Access Management

**SSO Integration**: Azure Government natively integrates with Microsoft Entra ID. The Borough's existing Entra ID tenant will serve as the identity provider for all cloud resources.

**MFA**: Microsoft Entra MFA enforced for all administrative access. Supports push notifications, TOTP, phone call, and hardware security keys.

**RBAC**: Azure RBAC with 100+ built-in roles. We will implement custom roles following principle of least privilege, with quarterly access reviews.

**PAM**: Microsoft Entra Privileged Identity Management (PIM) for just-in-time access elevation with approval workflows, time-bound assignments, and access reviews.

**Identity Governance**: Entra ID Governance with access packages, entitlement management, and quarterly access certification campaigns.



**Service Accounts**: Managed Identities for Azure resources eliminating credential management. Where service principals are required, automatic rotation every 90 days.

**Federation**: B2B collaboration via Entra External ID for inter-agency access without credential sharing. Trust relationships configurable per partner organization.

**Audit Logging**: All authentication and authorization events logged to Azure Monitor and Microsoft Sentinel with tamper-evident storage (immutable log retention).



### 4.2 Data Protection

**TLS**: All data in transit encrypted with TLS 1.3. TLS 1.2 and below disabled across all services. Certificate pinning for critical service-to-service communication.

**DLP**: Microsoft Purview DLP policies integrated across Azure services, SharePoint, Exchange, and Teams. Custom sensitive information types for Borough-specific data patterns.

**CMEK**: Customer-managed keys stored in Azure Key Vault with HSM backing (FIPS 140-2 Level 3 via Azure Key Vault Managed HSM).

**Data Classification**: Microsoft Purview Information Protection with sensitivity labels. Auto-classification for common data types with manual override capability.

**Key Management**: Azure Key Vault with automatic rotation policies, soft-delete protection, and purge protection. Dual-person authorization for critical key operations.

**TDE**: Transparent Data Encryption enabled by default for Azure SQL and other managed databases. CMEK-backed TDE available for enhanced control.



**Certificate Management**: Azure Key Vault certificate management with automated renewal for Let's Encrypt and DigiCert. Integration with Azure Application Gateway for automated deployment.

**Secrets Management**: Azure Key Vault for all secrets (API keys, connection strings, passwords). Full audit logging of all access and operations. Integration with Azure DevOps for CI/CD pipeline secrets.

**Data Masking**: Dynamic Data Masking for Azure SQL in production. Static masking via Microsoft Purview for non-production environment provisioning.

### 4.3 Threat Protection

**SOC**: Our 24/7 Security Operations Center is staffed by certified analysts (CISSP, GCIH, CEH) monitoring Borough environments around the clock. SOC is based in Anchorage with backup facility in Seattle.

**SIEM**: Microsoft Sentinel deployed in Azure Government with 180 days of hot storage (exceeds 90-day requirement). Custom analytics rules, workbooks, and hunting queries tailored for government environments.

**SOAR**: Sentinel automation rules and playbooks for automated response to common threats including brute force attacks, impossible travel alerts, and known malware indicators.

**Vulnerability Scanning**: Microsoft Defender Vulnerability Management with daily agent-based scanning and weekly authenticated network scans.

**EDR**: Microsoft Defender for Endpoint deployed on all virtual machines with automated investigation and response capabilities.

**Email Security**: Microsoft Defender for Office 365 Plan 2 with anti-phishing, safe attachments, safe links, and attack simulation training.

**Container Security**: Microsoft Defender for Containers with admission control, runtime protection, and vulnerability scanning integrated into CI/CD pipelines.

**API Security**: Azure API Management with threat detection. Microsoft Defender for APIs monitoring for anomalous access patterns.

**Deception Technology**: We deploy custom honeypots within the Borough's cloud environment using Azure Sentinel deception capabilities. Honeytokens placed in Active Directory, key vaults, and storage accounts as early warning indicators.

**Threat Intelligence**: Microsoft Defender Threat Intelligence integrated with Sentinel. Additional feeds from CISA, MS-ISAC, and Alaska specific threat intelligence sharing communities.

## Section 7: Migration Response

### 7.1 Migration Planning

**Discovery**: We will deploy Azure Migrate appliances within 2 weeks of contract start, completing full discovery and assessment within 25 days (ahead of 30-day requirement). Assessment covers compute, storage, network, and application dependencies.

**Migration Strategy**: Each workload categorized using the 6 Rs framework (Rehost, Replatform, Refactor, Repurchase, Retire, Retain). Recommendation based on TCO analysis, risk assessment, and Borough priorities.

**Zero-Downtime**: For critical applications, we employ blue-green deployment patterns with Azure Traffic Manager for seamless cutover. Database migrations use online migration tools (DMS) for continuous sync.

**Rollback**: Every migration wave includes documented rollback procedures tested in DR environment before production execution. Recovery validated within 2 hours.

**Parallel Run**: Minimum 30-day parallel run for all Tier 1 and Tier 2 applications. Extended to 60 days if requested by Borough application owners.

### 7.2 Data Migration

**Secure Transfer**: AzCopy with AES-256 encryption in transit and at rest. SHA-256 checksums validated pre and post transfer. Transfer logs retained for audit.

**Database Migration**: Azure Database Migration Service with schema conversion for incompatible sources. Pre-migration compatibility assessment and remediation guidance.

**Data Validation**: Automated validation framework comparing source and destination row counts, checksums, and sample data verification. 100% integrity certification signed off by Borough data owners.

**Progress Tracking**: Daily migration status reports via email and dashboard. Real-time progress tracking in Azure Migrate portal accessible to Borough team.

**Offline Transfer**: Azure Data Box (100 TB) and Data Box Heavy (1 PB) available for large datasets. NIST-compliant encryption with tamper-evident shipping. Chain of custody documentation provided.
